Business Capability Infrastructure for Autonomous Agents

Make your business usable by autonomous agents.

AgentFlow converts existing startup APIs and business workflows into discoverable, authenticated, policy-controlled capabilities that personal assistants and enterprise agents can safely understand and use.

Most AgentFlow capabilities are read-only or request-based. Transaction safety is an advanced module activated only when a capability changes business state.
Core Product Definition
"AgentFlow is the business capability layer for autonomous agents. It converts a company’s existing APIs and workflows into discoverable, authenticated, policy-controlled capabilities that agents can understand and invoke. Read-only and request-based capabilities work without transaction infrastructure. When a capability changes business state—such as booking, payment, inventory, cancellation, or transfer—the Transaction Safety Pack adds holds, idempotency, confirmation, reconciliation, and rollback."
Axiom: MCP makes a tool callable. AgentFlow makes a business usable by agents. Transaction safety protects the actions that matter most.

01 / Practical Demonstration

The 3-Level Capability Progression: Read, Request, Act

Not every agent interaction is a high-risk transaction. AgentFlow models business access in three progressive tiers, activating transaction safety only when real-world side effects occur.

LEVEL 1: READ
Agent-Readable
"Find available doctors near me."
The agent discovers the business, inspects services, searches pricing, and checks real-time availability. Read-only, zero side effects. 
// Read Action
GET /v1/capabilities/clinic/find_providers?area=indiranagar
Response: 200 OK
{
  "providers": [
    {"id": "c_44", "name": "Apex Spine", "price": 1200}
  ]
}
LEVEL 2: REQUEST
Agent-Requestable
"Ask the clinic for an appointment quote."
The agent submits inquiries, requests custom quotes, creates draft applications, or opens support cases. Structured, non-binding state. 
// Request Action
POST /v1/capabilities/clinic/request_appointment
Body: {"clinic_id": "c_44", "day": "Friday"}
Response: 200 OK
{
  "inquiry_id": "req_101",
  "offered_slot": "2026-10-16T16:00:00Z",
  "status": "DRAFT_OFFER"
}
LEVEL 3: ACT (TRANSACTION PACK)
Agent-Executable
"Book the appointment and pay."
The agent books, pays, cancels, or transfers. AgentFlow engages two-phase holds, idempotency locks, passkey confirmation, and sagas. 
// Executable Side Effect
POST /v1/capabilities/clinic/hold_slot
Header: X-AgentFlow-Mandate: mnd_8820f
Body: {"inquiry_id": "req_101", "amount": 1200}
Response: 403 ChallengeRequired
// Escalates to Passkey / In-App Confirmation

03 / Architectural Distinction

Why AgentFlow Exists if MCP Already Exists

The Model Context Protocol (MCP) solves tool discovery and RPC transport. It does not solve business capability synthesis, delegated user authority, stateful holds, or payment reconciliation.

Dimension Model Context Protocol (MCP) AgentFlow Capability Layer
Primary Job Exposes tool definitions and JSON-RPC method invocation to LLMs. Translates startup APIs into verified, policy-controlled business capabilities.
Protocol Scope Single open standard (MCP). Multi-protocol compilation: MCP + A2A protocol + WebMCP + REST OpenAPI specs.
State Awareness Stateless request/response RPC protocol. Stateful capability engine: Read, Request, and Act (with 2-phase holds).
Policy & Intent Relies on client-side prompt adherence or static API keys. Deterministic policy gate: budget ceilings, confirmation challenges, data redaction.
Transaction Safety None. Retried tool calls duplicate database mutations and charges. Optional Transaction Safety Pack: HTTP idempotency-key support, holds, and sagas.
Capability Verification None. Client agents guess tool reliability from string descriptions. Verification test lab issuing versioned "AgentFlow Verified" status.
Comparison Existing API Gateway (Kong, Google API Gateway) AgentFlow Business Capability Layer
What It Exposes Exposes raw HTTP endpoints and network routes. Exposes verified business capabilities and high-level workflows.
What It Authenticates Authenticates callers (OAuth tokens, API keys, mTLS). Enforces user intent, delegated action budgets, and confirmation gates.
Policy Layer Applies network policies (rate limits, WAF, CORS, IP allowlists). Applies business policies (price ceilings, cancellation windows, hold leases).
Traffic vs State Routes and load-balances network requests. Manages business capability lifecycle: Read, Request, and Act.
Core Protection Protects APIs from server crashes and DDoS attacks. Protects bookings, money, inventory, and customer trust.
04 / Product Architecture

The Six Core Modules of AgentFlow

AgentFlow operates as a comprehensive business capability layer between autonomous agent ecosystems and startup backends. Target p95 overhead: under 18ms in reference deployments.

MODULE 01
Capability Builder
Visual developer workbench that ingests existing OpenAPI 3.x specifications, SDKs, and database schemas to synthesize high-level business capabilities (find_doctor, check_availability, hold_slot) instead of exposing raw database CRUD.
MODULE 02
Agent Interface & Distribution
Multi-protocol compiler publishing capabilities simultaneously as Model Context Protocol (MCP) servers, A2A protocol agent cards, WebMCP integrations, REST APIs, and /.well-known/agent-capability.json manifests.
MODULE 03
Identity, Intent & Policy Layer
Cross-cutting authorization engine governing what the user allowed, which capability scopes the agent can invoke, scalar budget ceilings, time windows, data minimization filters, and out-of-band confirmation challenges for high-risk actions.
MODULE 04
Capability Runtime
High-performance proxy in Go providing request routing, credential brokering, rate limiting, event webhooks, backward-compatible versioning, error normalization, and real-time observability on agent invocation patterns.
MODULE 05 (OPTIONAL PACK)
Transaction Safety Pack
Dedicated distributed state engine for capabilities involving real-world side effects: two-phase holds with TTL leases, idempotency compatible with HTTP idempotency-key conventions, saga rollbacks, and signed audit receipts.
MODULE 06
Readiness & Conformance Lab
Capability verification and certification service that executes test suites against merchant staging environments (schema fuzzing, retry storms, hold timeouts, race conditions) before issuing versioned "AgentFlow Verified" badges.
What AgentFlow Is NOT
  • Not an LLM Provider: We do not train, tune, or host foundation models.
  • Not a Generic Chatbot: We do not provide consumer chat windows.
  • Not a Replacement for Stripe: We orchestrate business state; payment processors handle card settlement.
  • Not a Replacement for Kong: We manage business capability semantics, not L7 network routing.
  • Not Restricted to Transactions: We expose read-only catalogs, inquiries, and requests as first-class capabilities.
What AgentFlow IS

The layer that turns a startup's internal software into an external agent-facing product surface.

  • High-level business capability modeling engine.
  • Multi-protocol publishing layer (MCP, A2A, WebMCP, REST).
  • Deterministic identity, scope, and intent policy enforcement.
  • Optional managed transaction safety pack for stateful operations.
  • Capability verification and testing service.
05 / Cross-Cutting Policy Engine

Identity, Intent, and Policy Enforcement

Policy enforcement is not just for payments. It governs read-only capabilities as well: "Show me available doctors near Bangalore" permits searching clinics, but strictly blocks accessing other patients' medical records or dumping provider databases.

The 5-Stage Policy Evaluation Pipeline
Natural-Language Intent → Structured Action Contract → Deterministic Policy Checks → Business-State Validation → Allow / Deny / Hold / Escalate

Intent interpretation may use AI. Authorization decisions use typed, deterministic constraints:

Action Whitelist Resource Scope Price Ceiling (INR/USD) Data Minimization Filter Geographic Bounds Mandate TTL Confirmation Gate
Structured Capability Policy Contract
{
  "mandate_id": "mnd_8820f",
  "principal_id": "usr_9441",
  "target_capability": "clinic_services",
  "permissions": {
    "read_actions": ["find_providers", "get_availability"],
    "request_actions": ["request_appointment"],
    "executable_actions": ["hold_slot"],
    "requires_confirmation_for": ["confirm_booking", "execute_payment"]
  },
  "constraints": {
    "max_amount": 1500,
    "currency": "INR",
    "geofence": {"city": "Bangalore", "radius_km": 10},
    "service_category": "physiotherapy"
  },
  "expires_at": "2026-10-10T12:00:00Z"
}
Pragmatic 3-Tier Agent Identity Roadmap
A realistic progressive identity model rather than speculative universal attestation:
Level 1: Application Identity (Production Ready)
Registered agent application accounts, OAuth 2.0 client credentials, or API keys issued to verified platforms.
Level 2: Cryptographic Session Identity (Production Ready)
Agent signs every request payload using an ephemeral Ed25519 session keypair. Eliminates token replay attacks.
Level 3: Attested Identity (Ecosystem Roadmap)
Hardware enclave or secure execution environment attestation (AWS Nitro, Apple Secure Enclave) when supported by client.
06 / Optional High-Impact Module

Transaction Safety Pack: Safeguarding Side Effects

When an agent moves from reading information to modifying real-world business state (booking, purchasing, inventory allocation, cancellation), the Transaction Safety Pack activates.

Failure Scenario AgentFlow Automatic Response Guaranteed Outcome
Agent Times Out on Network AgentFlow checks transaction status in distributed state cache before processing any retried request. Zero duplicate execution; cached outcome returned immediately.
Payment Clears but Confirmation Lost Saga reconciliation engine queries provider booking status using shared idempotency key. Automatic retry of confirmation or automatic trigger of refund.
Temporary Hold Expires TTL lease fires in Redis key-expiration hook; slot unlocked in provider database. Inventory restored to human marketplace automatically.
Downstream Provider API Fails Saga coordinator initiates compensating transaction on payment gateway (void/refund). Zero unbooked debit charges; customer funds returned.
User Never Confirms Hold Hold reaches 10-minute TTL and expires silently; agent notified via webhook. No financial liability or persistent lockout created.
Agent Attempts Price Inflation Deterministic policy gate blocks request if amount exceeds mandate ceiling by ₹1. HTTP 403 Forbidden with exact violation details.

08 / Security & Adversarial Defense

Comprehensive Threat Model & Controls

Exposing capabilities to autonomous software introduces unique attack vectors. Here is our Threat → Control → Evidence defense architecture.

Threat Vector AgentFlow Mitigation Control Verifiable Evidence
Prompt Injection via Text Fields Payload field sanitization; prompt strings isolated from action control structures. Unit test suite & static AST validation log.
Tool-Description Poisoning Capability schemas cryptographically signed by provider; immutable runtime spec. Ed25519 signature verified on each discovery fetch.
Credential Theft & Replay Ephemeral session keypairs (PoP) and single-use confirmation challenge tokens. Token invalidation receipt in Redis state cache.
Duplicate Payment Retries HTTP Idempotency-Key support with atomic distributed cache locks. Cached response payload returned with Idempotent-Replay: true.
Stale Availability Race Two-phase temporary hold leases with 10-minute automatic TTL expiration. Hold creation record #h_xxx with expiration timestamp.
Unauthorized Upselling Deterministic policy checks against user mandate price ceiling and item whitelist. HTTP 403 IntentDriftBlocked with exact scalar discrepancy.
Excessive Data Access Data minimization filters; stripping internal records before agent response. Redacted response schema validation in gateway proxy.
Inventory Hoarding Attack Rate limits on concurrent holds per agent identity (max 2 active holds per principal). HTTP 429 ActiveHoldLimitExceeded response.
Regulatory & Compliance Boundary
Explicit Boundary: AgentFlow does not make medical, clinical, or financial advice decisions. It manages discovery, authentication, administrative scheduling, and transactional execution. Proprietary databases, patient records (PHI), and core business logic remain strictly within the provider's existing compliant infrastructure.
